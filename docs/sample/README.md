# Sample Cal AI export

`cal_ai_sample_export.pdf` is a made-up Cal AI export for App Review and for
testers who don't have one (#104). The import screen's **Try a sample export**
button imports the bundled copy of it through the real flow (parse, preview,
import).

- Name on the report: "Sample". No real person's data.
- Seven days, Mon Jan 6 to Sun Jan 12 2025: a fixed past week, so it never
  mixes into anyone's current days.
- 20 meals, each with macros that add up to its calories (within 5%). Jan 8
  has a name that wraps onto two lines; Jan 9 has a single snack, so it looks
  like a partial day.

| Day | kcal | Entries |
| --- | ---: | ---: |
| Jan 6 | 1,450 | 3 |
| Jan 7 | 1,625 | 4 |
| Jan 8 | 1,920 | 4 |
| Jan 9 | 230 | 1 |
| Jan 10 | 1,500 | 3 |
| Jan 11 | 1,610 | 3 |
| Jan 12 | 1,070 | 2 |

## Files

- `generate.py`: the meals, and the script that builds the other two files.
  Standard library only.
- `cal_ai_sample_export.html`: generated. One table per day, in the line
  shapes `CalAIParser` reads (title, `Start: · End:` line, date header,
  column header, food rows ending in the 8 value tokens, `TOTAL` line). Value
  cells are bottom-aligned, so a wrapped name's last line shares its row's
  baseline, as in a real export.
- `cal_ai_sample_export.pdf`: generated by printing the HTML with headless
  Chrome. Each table row extracts as one text line, as with Cal AI's PDFs.

## Regenerating

```sh
python3 docs/sample/generate.py   # --chrome PATH if Chrome isn't in /Applications
cp docs/sample/cal_ai_sample_export.pdf \
  features/pdf_import/pdf_import_presentation/assets/
```

Then update the expected days in
`features/pdf_import/pdf_import_data/test/sample_export_test.dart` and
`app/integration_test/sample_export_e2e_test.dart` if the meals changed. The
data test also fails if the asset and this copy differ.
